# Методика. Общие каталоги между хостом и виртуальной машиной

Общая инструкция по организации общего доступа к каталогу файловой системы хоста
из гостевой ОС. Не привязана к конкретной лабораторной работе — конкретный путь
на хосте и точка монтирования в гостевой ОС задаются в задании.

## 1. Как это устроено в разных гипервизорах

| Гипервизор | Механизм | Протокол передачи |
|---|---|---|
| VirtualBox | Shared Folders (Guest Additions) | vboxsf, либо 9p (если явно включён) |
| QEMU/KVM | virtfs | 9p (VirtIO-9P) |
| VMware | HGFS (Host-Guest File System) | собственный протокол VMware |

**9p** — сетевой протокол файловой системы (изначально из Plan 9), который
некоторые гипервизоры используют как транспорт для передачи файлов между
хостом и гостем без «настоящей» сети. Гостевая ОС монтирует шару как обычную
файловую систему через `mount -t 9p`.

## 2. Настройка на стороне хоста

Общий порядок для любого гипервизора:

1. Выбрать/создать каталог на хосте, который будет расшарен (например
   `~/vm-shared/<имя>`).
2. В настройках ВМ добавить общую папку (Shared Folder), указав:
   - путь на хосте;
   - имя шары (произвольное, гостевая ОС будет ссылаться на неё по этому имени);
   - при необходимости — доступ только для чтения или чтение/запись;
   - если гипервизор поддерживает выбор протокола — явно выбрать **9p**.
3. При необходимости включить «автомонтирование» на уровне гипервизора — но для
   учебных целей полезнее смонтировать вручную (пункт 3), чтобы явно увидеть
   каждый шаг.

Для VirtualBox: Settings → Shared Folders → Add → указать путь на хосте, имя
шары; для использования именно 9p может понадобиться включить соответствующую
опцию/расширение, в зависимости от версии VirtualBox — проверьте официальную
документацию используемой версии.

Для QEMU при запуске из командной строки:

```bash
-virtfs local,path=/home/user/vm-shared,mount_tag=hostshare,security_model=mapped-xattr,id=hostshare
```

## 3. Монтирование в гостевой ОС (протокол 9p)

1. Убедиться, что в ядре гостя есть поддержка 9p (в большинстве современных
   дистрибутивов — есть по умолчанию как модуль):
   ```bash
   sudo modprobe 9p
   sudo modprobe 9pnet_virtio
   ```
2. Создать точку монтирования:
   ```bash
   sudo mkdir -p /mnt/hostshare
   ```
3. Смонтировать вручную:
   ```bash
   sudo mount -t 9p -o trans=virtio,version=9p2000.L,msize=104857600 hostshare /mnt/hostshare
   ```
   Где:
   - `hostshare` — тег шары (mount tag), заданный на стороне хоста/гипервизора;
   - `trans=virtio` — транспорт через VirtIO (стандартно для ВМ);
   - `version=9p2000.L` — версия протокола с расширенной поддержкой Linux-семантики
     (права доступа, символические ссылки и т.д.) — рекомендуется, если доступна;
   - `msize` — максимальный размер пакета обмена, большее значение обычно
     повышает пропускную способность.

## 4. Автомонтирование при загрузке (`/etc/fstab`)

```
hostshare   /mnt/hostshare   9p   trans=virtio,version=9p2000.L,msize=104857600,rw,_netdev   0   0
```

Опция `_netdev` указывает системе, что устройство появляется после поднятия
виртуальных сетевых интерфейсов — это уменьшает риск ошибок монтирования при
раннем старте системы.

Проверить, что запись в `fstab` корректна, без перезагрузки:

```bash
sudo mount -a
```

## 5. Права доступа

Поведение с правами доступа файлов на шаре зависит от `security_model`,
заданного на стороне хоста (для QEMU) или от режима работы гипервизора:

- `security_model=mapped-xattr` / `mapped-file` — права и владелец файлов
  эмулируются и хранятся отдельно, реальные права на хосте не меняются;
- `security_model=passthrough` — гостевая ОС должна иметь права, совпадающие с
  правами на хосте (обычно требует запуска гипервизора с повышенными правами);
- `security_model=none` — упрощённый режим без отображения прав, обычно все
  файлы видны с одинаковыми правами.

Если после монтирования файлы недоступны на запись или показывают неожиданного
владельца — в первую очередь проверяйте именно этот параметр.

## 6. Проверка работы

```bash
# со стороны гостя — создать файл
echo "test" > /mnt/hostshare/from-guest.txt

# на хосте — убедиться, что файл появился в расшаренном каталоге
cat ~/vm-shared/from-guest.txt
```

## 7. Типичные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `mount: unknown filesystem type '9p'` | Не загружены модули ядра | `sudo modprobe 9p 9pnet_virtio` |
| `No such device` при монтировании по тегу | Неверный `mount_tag`, либо шара не подключена на уровне гипервизора | Сверить имя шары в настройках ВМ и в команде `mount` |
| Файлы видны, но не редактируются | Шара подключена в режиме read-only на уровне гипервизора | Изменить режим доступа шары на «чтение/запись» в настройках ВМ |
| Изменения с хоста не видны в госте (или наоборot) без перемонтирования | Кэширование на уровне протокола | Использовать `cache=none` или `cache=loose` в опциях монтирования в зависимости от требуемого баланса скорость/актуальность данных |
| После перезагрузки шара не подключается | Ошибка в строке `/etc/fstab`, либо шара недоступна на момент монтирования | Проверить `dmesg`/`journalctl -xe`, убедиться, что указана опция `_netdev` |
