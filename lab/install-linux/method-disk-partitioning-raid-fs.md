# Методика. Разметка дисков, RAID и файловые системы

Общая инструкция по работе с дисками в Linux: от разметки одного диска до сборки
программного RAID-массива и установки на него файловой системы. Документ не
привязан к конкретной лабораторной работе — конкретные размеры, число дисков и
уровень RAID задаются в задании.

## 1. Базовые понятия

- **Блочное устройство** — диск целиком виден как `/dev/sda`, `/dev/sdb`, …
  (или `/dev/nvme0n1` для NVMe, `/dev/vda` для некоторых виртуальных дисков).
- **Раздел (partition)** — часть диска, видна как `/dev/sda1`, `/dev/sda2`, …
- **Таблица разделов**:
  - **MBR** (msdos) — старый формат, максимум 4 основных раздела (или 3 основных
    + 1 расширенный с логическими), лимит размера диска 2 ТБ;
  - **GPT** — современный формат, до 128 разделов, поддержка дисков большого
    объёма. Рекомендуется по умолчанию, если нет причин использовать MBR.
- Посмотреть текущую разметку всех дисков:
  ```bash
  lsblk
  # или подробнее:
  sudo fdisk -l
  ```

## 2. Инструменты разметки

| Инструмент | Особенности |
|---|---|
| `fdisk` | Интерактивный, работает с MBR и (в современных версиях) с GPT |
| `parted` / `parted -a` | Поддерживает скриптовый режим, удобен для GPT |
| `cfdisk` | Псевдографический интерфейс поверх той же логики, что и fdisk — проще для начала |
| `gdisk` | Аналог fdisk специально для GPT |

Пример создания одного раздела на весь диск через `parted` в неинтерактивном
режиме:

```bash
sudo parted /dev/sdb --script mklabel gpt
sudo parted /dev/sdb --script mkpart primary 0% 100%
```

Пример через `fdisk` (интерактивно):

```bash
sudo fdisk /dev/sdb
# n  -> новый раздел
# p  -> основной (для MBR) / Enter для значений по умолчанию
# w  -> записать изменения на диск
```

После создания разделов ядро может не сразу увидеть изменения — обновите таблицу
разделов:

```bash
sudo partprobe /dev/sdb
```

## 3. Файловые системы

### 3.1 Обзор

| ФС | Особенности | Пакет с утилитами (Debian/Ubuntu) |
|---|---|---|
| ext4 | Устойчивая, используется по умолчанию в большинстве дистрибутивов | `e2fsprogs` (обычно уже установлен) |
| XFS | Хорошо работает с большими файлами и параллельным вводом-выводом | `xfsprogs` |
| Btrfs | Снапшоты, встроенное RAID-подобное зеркалирование, сжатие | `btrfs-progs` |
| F2FS | Оптимизирована под flash-накопители | `f2fs-tools` |
| JFS | Лёгкая журналируемая ФС, низкие накладные расходы | `jfsutils` |

> **Про пакетный менеджер.** Все команды установки пакетов в этом документе
> даны через `apt` (Debian/Ubuntu). Названия пакетов с утилитами для файловых
> систем (`xfsprogs`, `btrfs-progs`, `f2fs-tools`, `jfsutils`) и для RAID
> (`mdadm`) одинаковы и в репозиториях Arch — просто ставьте их через
> `pacman -S <пакет>` вместо `apt install -y <пакет>`.

> **Отдельные типы разделов для загрузчика** (ESP при UEFI, `bios_grub` при
> BIOS+GPT) разбираются в `method-bootloader-grub.md` — они не несут обычную
> файловую систему и создаются иначе, чем разделы из этого документа.

### 3.2 Создание файловой системы

Общий вид команды: `mkfs.<тип> <устройство>`.

```bash
sudo apt install -y xfsprogs        # если утилита ещё не установлена
sudo mkfs.xfs /dev/sdb1

# другие примеры:
sudo mkfs.ext4 /dev/sdb1
sudo mkfs.btrfs /dev/sdb1
sudo mkfs.f2fs /dev/sdb1
sudo mkfs.jfs /dev/sdb1
```

### 3.3 Монтирование

Разово:

```bash
sudo mkdir -p /mnt/data
sudo mount /dev/sdb1 /mnt/data
```

Постоянно (переживает перезагрузку) — добавить строку в `/etc/fstab`. Лучше
указывать не путь устройства (`/dev/sdb1`), а его UUID — он не меняется при
переподключении дисков в другом порядке:

```bash
sudo blkid /dev/sdb1
# UUID="xxxxxxxx-xxxx-...."  TYPE="xfs"
```

Строка в `/etc/fstab`:

```
UUID=xxxxxxxx-xxxx-....   /mnt/data   xfs   defaults   0   2
```

Применить без перезагрузки и проверить, что нет опечаток:

```bash
sudo mount -a
```

## 4. Программный RAID (mdadm)

### 4.1 Уровни RAID (кратко)

| Уровень | Мин. дисков | Идея | Отказоустойчивость |
|---|---|---|---|
| RAID 0 | 2 | Данные «полосами» (striping) распределяются по всем дискам | Нет — отказ любого диска = потеря всех данных |
| RAID 1 | 2 | Полное зеркалирование данных | Да — переживает отказ одного диска (из пары) |
| RAID 5 | 3 | Striping + контроль чётности, распределённый по дискам | Да — переживает отказ одного диска |
| RAID 6 | 4 | Как RAID 5, но с двойной чётностью | Да — переживает отказ двух дисков |
| RAID 10 | 4 | Зеркала, объединённые страйпингом | Да |

RAID 0 повышает производительность, но **не** является резервным копированием.
RAID 1/5/6/10 добавляют отказоустойчивость ценой части полезного объёма и/или
производительности записи.

### 4.2 Установка утилит

```bash
sudo apt install -y mdadm
# на Arch: sudo pacman -S mdadm
```

### 4.3 Создание массива

Пример — RAID 1 из двух дисков:

```bash
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

Пример — RAID 5 из трёх дисков:

```bash
sudo mdadm --create /dev/md0 --level=5 --raid-devices=3 /dev/sdb1 /dev/sdc1 /dev/sdd1
```

Пример — RAID 0 из двух дисков:

```bash
sudo mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb1 /dev/sdc1
```

После создания массив сразу доступен как единое блочное устройство `/dev/md0` —
дальше с ним работают как с обычным диском: создают файловую систему (раздел 3),
монтируют, прописывают в `/etc/fstab`.

### 4.4 Сохранение конфигурации массива

Чтобы массив собирался автоматически при загрузке:

```bash
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
```

### 4.5 Диагностика состояния массива

```bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

В выводе `--detail` важны поля `State` (`clean` — всё в порядке, `degraded` —
массив работает не в полном составе) и список устройств со статусами
(`active sync`, `faulty`, `spare`).

### 4.6 Имитация отказа диска и восстановление

```bash
# пометить диск как отказавший
sudo mdadm /dev/md0 --fail /dev/sdc1

# убедиться, что массив деградировал, но (для RAID 1/5/6/10) продолжает работать
cat /proc/mdstat

# исключить отказавший диск из массива
sudo mdadm /dev/md0 --remove /dev/sdc1

# добавить диск обратно (или новый диск на замену) — начнётся ребилд
sudo mdadm /dev/md0 --add /dev/sdc1

# наблюдать за прогрессом восстановления
watch cat /proc/mdstat
```

Для RAID 0 отказ любого диска из массива равносилен потере всего массива —
это ожидаемое поведение, а не ошибка настройки; массив в этом случае нужно
пересоздавать заново.

### 4.7 Добавление резервного диска (hot spare)

Резервный диск подключается к массиву, но не используется, пока другой диск не
откажет — тогда ребилд на него начинается автоматически:

```bash
sudo mdadm /dev/md0 --add-spare /dev/sdd1
```

### 4.8 Полное удаление массива

Если нужно пересобрать массив с нуля:

```bash
sudo umount /mnt/raid
sudo mdadm --stop /dev/md0
sudo mdadm --zero-superblock /dev/sdb1 /dev/sdc1 /dev/sdd1
```

## 5. Типичные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `mdadm: no devices listed in conf file` при пересборке после перезагрузки | Конфигурация массива не сохранена | Выполнить п. 4.4 |
| Раздел не виден после создания | Таблица разделов ядра не обновилась | `sudo partprobe`, либо перезагрузка |
| `mount: wrong fs type` | ФС на разделе не соответствует указанной в команде `mount` | Проверить реальный тип через `blkid` или `lsblk -f` |
| Массив в состоянии `degraded` сразу после создания | Нормально для RAID 5/6 — идёт начальная синхронизация чётности | Дождаться завершения (`cat /proc/mdstat`), это не ошибка |
