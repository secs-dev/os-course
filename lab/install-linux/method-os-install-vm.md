# Методика. Развёртывание виртуальной машины и установка Linux

Этот документ описывает общие принципы работы с виртуальными машинами и установки
Linux-дистрибутивов через установщик. Он не привязан к конкретной лабораторной
работе, дистрибутиву или гипервизору — конкретные параметры (имя машины, размеры
разделов и т.д.) задаются в задании конкретной ЛР.

## 1. Понятия виртуализации

- **Гипервизор второго типа** (VirtualBox, VMware Workstation/Fusion, QEMU/KVM
  через libvirt) — программа, запускаемая поверх обычной ОС хоста, которая
  эмулирует аппаратное обеспечение для гостевой ОС.
- **Аппаратная виртуализация** (Intel VT-x / AMD-V) должна быть включена в
  BIOS/UEFI хоста — без неё гипервизор либо не запустится, либо будет работать
  крайне медленно (программная эмуляция).
- Гостевой ОС выделяются виртуальные ресурсы: количество vCPU, объём RAM,
  один или несколько виртуальных дисков, один или несколько сетевых адаптеров.
  Эти ресурсы можно менять после создания ВМ (в выключенном состоянии), кроме
  некоторых параметров диска.

## 2. Создание виртуальной машины

Общий порядок действий одинаков почти для любого гипервизора:

1. **Создать новую ВМ**, указав тип и версию гостевой ОС (это влияет на
   предлагаемые по умолчанию настройки, но не ограничивает жёстко, что можно
   поставить).
2. **Выделить CPU** — число виртуальных ядер. Не следует выделять больше
   ядер, чем физически доступно на хосте.
3. **Выделить RAM** — с запасом для хоста: не отдавайте гостю всю физическую
   память.
4. **Создать виртуальный диск**:
   - формат (VDI/VMDK/QCOW2 — зависит от гипервизора);
   - тип выделения места — «динамический» (растёт по мере заполнения, экономит
     место на хосте) или «фиксированный» (сразу занимает весь заявленный объём,
     быстрее в работе);
   - размер — задаётся в задании конкретной ЛР.
5. **Подключить установочный образ** (ISO) как виртуальный оптический привод —
   это будет загрузочный носитель для установки ОС.
6. **Настроить сеть** — см. раздел 3 ниже и файл `method-network-ssh.md`.
7. Убедиться, что в настройках загрузки ВМ первым загрузочным устройством стоит
   оптический привод (или что ВМ вообще увидит там загрузочный ISO).
8. **Выбрать режим прошивки — BIOS (Legacy) или UEFI.** Это нужно решить *до*
   установки ОС: режим прошивки определяет, какая нужна таблица разделов
   (MBR/GPT) и как ставится загрузчик (см. `method-bootloader-grub.md`). В
   VirtualBox режим задаётся в Settings → System → чекбокс «Enable EFI»
   (включён = UEFI, выключен = BIOS/Legacy, это значение по умолчанию). После
   установки системы сменить режим без переустановки нельзя.

После первой успешной загрузки с установочного образа лишние настройки (порядок
загрузки, при необходимости — отключение ненужных vCPU) можно скорректировать.

## 3. Сетевые режимы ВМ (кратко)

Подробности проброса портов и SSH — в `method-network-ssh.md`. Здесь — только
выбор режима на этапе создания ВМ:

| Режим | Гостевая ОС видна извне? | Типичное применение |
|---|---|---|
| NAT | Нет (только исходящий трафик и явно проброшенные порты) | Изолированные учебные ВМ с доступом по проброшенному порту |
| Bridged / Мост | Да, получает адрес в сети хоста | ВМ, к которой нужен прямой доступ по сети как к отдельному узлу |
| Host-only / Internal | Только из хоста / только между ВМ | Изолированные лабораторные стенды без выхода в интернет |

Для большинства учебных задач, где нужен доступ к ВМ по SSH с хоста и не нужен
доступ к ВМ извне сети хоста, достаточно **NAT с пробросом порта**.

## 4. Установка ОС через установщик

Этот раздел описывает дистрибутивы **с мастером-установщиком** (Debian, Ubuntu
Server и т.п.). У части дистрибутивов (в первую очередь — Arch Linux) мастера
нет: после загрузки с ISO вы сразу попадаете в командную строку и выполняете
все шаги ниже вручную, теми же командами, что использовал бы установщик у
себя «под капотом». Этот путь подробно описан в отдельном документе —
`method-arch-manual-install.md`. Понятия (разметка, локаль, hostname и т.д.)
там те же самые, отличается только то, что их приходится явно проговаривать
командами, а не выбирать в меню.

Установщики обычно последовательно запрашивают:

1. **Язык / локализацию системы** — влияет на язык сообщений и на локали
   (`LANG`, кодировки, форматы дат/чисел).
2. **Раскладки клавиатуры** — можно указать несколько, переключение между ними
   настраивается позже.
3. **Имя хоста (hostname) и домен** — идентификация машины в сети;
   `hostname.domain` образует полное доменное имя (FQDN).
4. **Часовой пояс**.
5. **Разметку диска** — см. раздел «Разметка диска в установщике» ниже и файл
   `method-disk-partitioning-raid-fs.md` для более глубокого погружения.
6. **Учётные записи** — пароль root (если он используется отдельно) и как
   минимум один обычный пользователь.
7. **Выбор ПО для установки** (tasksel/группы пакетов) — например, «SSH server»,
   «стандартные системные утилиты», при желании — графическое окружение.
8. **Установку загрузчика** (обычно GRUB) — как правило, ставится на основной
   диск автоматически, если явно не указано иное.

### Текстовый vs графический установщик

Текстовый (ncurses) установщик работает быстрее и стабильнее в ВМ с
ограниченными ресурсами, не требует эмуляции видеокарты с 3D-ускорением и лучше
подходит для серверных систем без графической оболочки. Логика шагов та же, что
и в графическом установщике — отличается только интерфейс (стрелки/Tab/Enter
вместо мыши).

### Разметка диска в установщике

Установщики обычно предлагают два режима:

- **Автоматическая (guided) разметка** — установщик сам создаёт разделы по
  выбранной схеме (один раздел под всё; отдельно `/home`; отдельно `/home`,
  `/var`, `/tmp` и т.д.).
- **Ручная разметка** — вы сами создаёте разделы на диске: указываете размер,
  файловую систему и точку монтирования для каждого. Обычно необходимый минимум:
  - раздел под `/` (корень);
  - раздел (или файл) под `swap`;
  - опционально отдельные разделы под `/home`, `/var` и др.

  Порядок действий при ручной разметке в установщике Debian: выбрать диск →
  создать новую таблицу разделов (если диск пустой) → создать раздел, указать
  размер → выбрать «использовать как» (файловую систему) → выбрать точку
  монтирования → повторить для следующего раздела → «завершить разметку и
  записать изменения на диск».

  Общие принципы устройства разделов, таблиц разделов (MBR/GPT) и файловых
  систем разобраны подробнее в `method-disk-partitioning-raid-fs.md` — используйте
  его, если непонятно, что означает тот или иной пункт меню установщика.

## 5. Первые шаги после установки

После первой загрузки установленной системы полезно сразу проверить:

```bash
# версия и релиз дистрибутива
cat /etc/os-release

# сетевые интерфейсы и адреса
ip addr

# состояние ключевых служб (например, ssh)
systemctl status ssh

# обновление списка пакетов и самих пакетов
sudo apt update && sudo apt upgrade -y
```

## 6. Типичные проблемы и их решение

| Симптом | Возможная причина | Решение |
|---|---|---|
| ВМ не запускается / ошибка про VT-x/AMD-V | Аппаратная виртуализация выключена в BIOS/UEFI, либо конфликтует с другим гипервизором (Hyper-V) | Включить VT-x/AMD-V в BIOS; на Windows — отключить Hyper-V/Device Guard, если он занят другим гипервизором |
| Установщик не видит диск | Несовместимый режим контроллера диска (например, диск создан под NVMe, а установщик грузится с SATA-образом) | Проверить/сменить тип контроллера диска в настройках ВМ |
| После установки нет сети внутри ВМ | Сетевой адаптер ВМ выключен или неверно выбран режим | Проверить, что адаптер включён и подключён (Attached to: NAT/Bridged), выполнить `ip link` внутри гостя |
| Установщик зависает на загрузке пакетов | Нет доступа в сеть на момент установки (актуально для netinst-образов) | Проверить сетевые настройки ВМ до запуска установки; для NAT — сеть должна работать «из коробки» |
| Долгая/медленная работа ВМ | Программная эмуляция вместо аппаратной виртуализации | Проверить, что VT-x/AMD-V активны и гипервизор их использует |
