# Методика. Сеть и удалённый доступ по SSH

Общая инструкция по сетевым режимам виртуальных машин и настройке удалённого
доступа по SSH. Не привязана к конкретной лабораторной работе — конкретные
номера портов и параметры сети задаются в задании.

## 1. Сетевые режимы ВМ

| Режим | Как работает | Доступ к ВМ снаружи | Доступ ВМ в интернет |
|---|---|---|---|
| **NAT** | Гипервизор транслирует адреса, ВМ находится «за роутером» | Только через явно проброшенные порты | Есть |
| **Bridged (мост)** | Виртуальный адаптер подключается напрямую к физической сети хоста | Да, ВМ получает адрес в той же сети, что и хост | Есть |
| **Host-only / Internal** | Изолированная виртуальная сеть | Только с хоста (host-only) или вообще ни с кем снаружи (internal) | Нет |

Для учебных стендов, где нужен доступ по SSH с хоста, но не нужен доступ к ВМ
из внешней сети, обычно достаточно **NAT + проброс порта**.

## 2. Проброс портов (NAT) в VirtualBox

Настройки ВМ → Network → адаптер в режиме NAT → **Port Forwarding**:

| Name | Protocol | Host IP | Host Port | Guest IP | Guest Port |
|---|---|---|---|---|---|
| ssh | TCP | (пусто или 127.0.0.1) | 2222 | (пусто) | 22 |

После этого с хоста ВМ доступна так:

```bash
ssh -p 2222 <логин>@127.0.0.1
```

Для QEMU эквивалентная настройка задаётся при запуске флагом:

```bash
-netdev user,id=net0,hostfwd=tcp::2222-:22
```

Для VMware — через редактирование `vmnetnat.conf` или настройки NAT-адаптера в
интерфейсе Workstation/Fusion (Edit → Virtual Network Editor → NAT Settings →
Port Forwarding).

## 3. Установка и включение SSH-сервера

Если сервер не был установлен на этапе установки ОС:

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

> **На Arch** пакет называется `openssh` (`sudo pacman -S openssh`), а имя
> службы — `sshd`, а не `ssh`: `sudo systemctl enable --now sshd`. Дальше по
> тексту этого документа везде, где встречается `systemctl ... ssh`, на Arch
> нужно подставлять `sshd`.

## 4. Базовая конфигурация `sshd`

Файл конфигурации: `/etc/ssh/sshd_config`. Основные параметры:

```
Port 22
PermitRootLogin no
PasswordAuthentication yes
PubkeyAuthentication yes
```

После изменения конфигурации обязательно перезапустить службу и проверить
синтаксис:

```bash
sudo sshd -t              # проверка конфигурации без применения
sudo systemctl restart ssh
```

## 5. Аутентификация по ключу

### 5.1 Генерация пары ключей на клиенте (хосте)

```bash
ssh-keygen -t ed25519 -C "guest@lab"
# по умолчанию сохранится в ~/.ssh/id_ed25519 (приватный) и id_ed25519.pub (публичный)
```

### 5.2 Копирование публичного ключа на сервер (ВМ)

Автоматически:

```bash
ssh-copy-id -p 2222 guest@127.0.0.1
```

Вручную (если `ssh-copy-id` недоступен) — на стороне сервера:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "<содержимое id_ed25519.pub>" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

Права доступа на `~/.ssh` (700) и `authorized_keys` (600) обязательны — при
слишком открытых правах sshd молча откажется использовать этот файл.

### 5.3 Отключение входа по паролю (после проверки, что вход по ключу работает)

```
PasswordAuthentication no
```

## 6. Проверка подключения

```bash
ssh -p 2222 -v guest@127.0.0.1
```

Флаг `-v` (можно `-vvv` для большей детализации) показывает подробности
установления соединения — какие ключи предлагаются, какой метод
аутентификации в итоге сработал и т.д.

## 7. Типичные проблемы

| Симптом | Возможная причина | Решение |
|---|---|---|
| `Connection refused` | Служба ssh не запущена, либо порт проброшен неверно | `systemctl status ssh` на ВМ, проверить таблицу проброса портов |
| `Connection timed out` | Неверный режим сети (например, bridged без DHCP-адреса) или блокировка firewall на хосте | Проверить `ip addr` на ВМ, проверить настройки firewall хоста |
| `Permission denied (publickey)` | Неверные права на `~/.ssh`/`authorized_keys`, либо ключ не скопирован | Проверить права (700/600), проверить содержимое `authorized_keys` |
| `Permission denied (publickey,password)` при выключенном `PasswordAuthentication` | Ключ не настроен, а вход по паролю уже отключён | Временно включить `PasswordAuthentication yes`, настроить ключ, затем отключить снова |
| Изменения `sshd_config` не применяются | Забыт перезапуск службы | `sudo systemctl restart ssh` |
